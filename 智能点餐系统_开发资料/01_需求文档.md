# 智能点餐系统 — 需求文档 v1.0

> 基于 xshell 内部培训资料整理
> 日期：2026-05-12

---

## 一、项目背景

公司需要一个**智能点餐推荐系统**。

用户说"我想吃XXX"，系统自动识别食物、分析口味、查询附近餐厅、给出个性化推荐。

---

## 二、核心业务流程（4步走）

```
用户上传图片/输入文字 → 识别食物 → 检索相似菜品 → 查询附近餐厅 → 生成推荐
```

### 详细步骤：

**Step 1 — 食物识别**
- 用户上传一张食物图片，或者输入文字描述
- 系统调用"图像识别"能力，判断这是什么菜
- 例如：图片 → 判断为"宫保鸡丁"

**Step 2 — 口味分析 + 菜品检索**
- 根据识别的食物，分析它的口味标签（辣度、菜系、口感等）
- 从向量数据库（已有菜品库）里检索"相似菜品"
- 例如：宫保鸡丁 → 口味标签：川菜、微辣 → 检索到"鱼香肉丝"、"麻婆豆腐"

**Step 3 — 查询附近餐厅**
- 获取用户当前地理位置（前端传经纬度）
- 查询 MySQL：哪些餐厅有这些菜 / 用户历史吃过哪些
- 调用高德地图 API：查附近餐厅的实时距离、排队人数、评分

**Step 4 — 生成推荐**
- 把以上信息全部喂给 LLM
- LLM 综合考虑：距离、口味偏好、排队情况、历史记录
- 返回一个带理由的推荐结果

## 四、数据源说明

### 4.1 MySQL 数据库（结构化数据）

- **菜品表** `dishes` — 菜品ID、名称、口味标签、所属餐厅、价格
- **餐厅表** `restaurants` — 餐厅ID、名称、地址、坐标、评分、排队人数
- **用户表** `users` — 用户ID、偏好口味、历史点餐记录
- **订单表** `orders` — 订单ID、用户ID、餐厅ID、菜品ID、时间

### 4.2 Pinecone 向量数据库（相似度检索）

- 存储已入库菜品的向量embedding
- 支持：余弦相似度检索
- 用途：给定一个食物，检索相似口味的菜品

### 4.3 高德地图 API（外部服务）

- 地理编码：将地址转为坐标
- 周边搜索：给定坐标，搜索附近餐厅
- 路径规划：计算到餐厅的距离和耗时
- 实时数据：餐厅排队人数

### 4.4 通义千问 LLM（推理能力）

- 食物识别（视觉）
- 口味分析（文本）
- 生成推荐理由（推理）

## 五、API 接口清单

### 接口 1：智能推荐（主流程）
```
POST /api/v1/recommend
输入：user_id, 图片/文字描述, 经纬度
输出：推荐结果列表（餐厅 + 理由）
```

### 接口 2：食物识别
```
POST /api/v1/recognize
输入：图片文件 或 文字描述
输出：食物名称 + 置信度
```

### 接口 3：附近餐厅查询
```
GET /api/v1/nearby_restaurants
输入：经纬度, 距离范围(米)
输出：餐厅列表
```

### 接口 4：口味分析
```
POST /api/v1/analyze_taste
输入：食物名称
输出：口味标签字典
```

## 六、非功能性需求

| 维度 | 要求 |
|------|------|
| 响应速度 | 推荐接口 < 5秒 |
| 可扩展性 | 工具层松耦合，方便替换底层实现 |
| 可维护性 | 分层清晰，代码结构符合公司规范 |
| 兼容性 | 支持接入其他LLM（不硬绑定通义） |

## 七、项目约束

- 语言：Python 3.10+
- Web框架：FastAPI
- 数据库：MySQL 8.0
- 向量库：Pinecone
- LLM：通义千问（阿里云 DashScope）
- 地图：高德地图 Web服务 API
