## 二、模块职责说明

### 2.1 API 层 — `api/main.py`

**职责**：接收用户请求，定义数据模型，路由分发

**核心类**：
- `RecommendRequest` — 推荐请求参数模型
- `RecommendResponse` — 推荐返回数据模型
- 路由函数：`POST /api/v1/recommend`

**不对业务逻辑负责**，只负责：
- 参数校验
- 格式转换
- 异常捕获

---

### 2.2 智能体层 — `agent/smart_agent.py`

**职责**：编排整个推荐流程的决策中枢

**核心逻辑**：ReAct 循环（思考-行动-观察）

```
用户请求
  │
  ▼
┌──────────────────────┐
│ 1. 解析意图          │ ← LLM 判断用户想要什么
└──────────┬───────────┘
           ▼
┌──────────────────────┐
│ 2. 选择工具 + 调用   │ ← db_tool / amap_tool / llm_tool
└──────────┬───────────┘
           ▼
┌──────────────────────┐
│ 3. 收集结果          │ ← 汇总各工具返回
└──────────┬───────────┘
           ▼
┌──────────────────────┐
│ 4. 生成推荐回复      │ ← LLM 综合所有信息，给出最终推荐
└──────────────────────┘
```

**不做什么**：
- 不直接读写数据库
- 不直接调外部API
- 只负责"调度"

---

### 2.3 工具层 — `tools/`

**职责**：封装对外部服务的调用，对上层提供干净的Python接口**

| 工具文件 | 底层依赖 | 对外提供 |
|---------|---------|---------|
| `db_tool.py` | MySQL | query_dishes_by_taste()、query_user_profile()、query_restaurant_by_id() |
| `pinecone_tool.py` | Pinecone | search_similar_dishes() |
| `amap_tool.py` | 高德地图API | get_nearby_restaurants()、get_distance() |
| `llm_tool.py` | 阿里云DashScope | recognize_food_image()、analyze_taste()、generate_recommendation() |

**工具设计原则**：
- 每个工具职责单一
- 返回Python字典，不返回原始API响应
- 异常自己处理，不往上抛

---

### 2.4 服务层 — `service/diancan_service.py`

**职责**：业务逻辑编排，承上启下

```
API层调用
    │
    ▼
┌─────────────────────────────────────────────┐
│  diancan_service.recommend()                │
│                                             │
│  ① 调用 llm_tool.recognize_food_image()     │
│     → 识别食物名称                          │
│                                             │
│  ② 调用 llm_tool.analyze_taste()            │
│     → 获取口味标签                          │
│                                             │
│  ③ 调用 pinecone_tool.search_similar()      │
│     → 检索相似菜品                          │
│                                             │
│  ④ 调用 db_tool.query_user_history()        │
│     → 获取用户历史偏好                      │
│                                             │
│  ⑤ 调用 amap_tool.get_nearby_restaurants()  │
│     → 获取附近餐厅                          │
│                                             │
│  ⑥ 组装上下文，调用 llm_tool.generate()      │
│     → 生成推荐结果                          │
└─────────────────────────────────────────────┘
    │
    ▼
返回给 Agent
```

---

### 2.5 提示词层 — `prompt/*.txt`

**职责**：存放提示词模板，解耦硬编码

| 文件 | 用途 |
|------|------|
| `system_prompt.txt` | 给LLM的角色设定：你是一个美食推荐专家 |
| `recognize_prompt.txt` | 食物识别的提示词模板 |
| `taste_prompt.txt` | 口味分析的提示词模板 |
| `recommend_prompt.txt` | 生成推荐结果的提示词模板 |

## 六、技术选型理由

| 组件 | 选型 | 理由 |
|------|------|------|
| Web框架 | FastAPI | 轻量、异步、自动文档、性能好 |
| LLM调用 | LangChain | 统一接口、方便切换底座模型 |
| 向量库 | Pinecone | 托管服务、免运维、查询快 |
| 地图 | 高德 | 国内数据全、API稳定、费用低 |
| 数据库 | MySQL | 结构化数据存储，公司现有 |
